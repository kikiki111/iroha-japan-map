## 1. アプリ概要

| 項目 | 内容 |
|---|---|
| アプリ名 | いろは（Iroha） |
| バンドルID | `com.qumo.Iroha` |
| 表示バージョン | 1.0.5（Build 1） |
| 対応OS | iOS 18.0 以上 |
| 言語 | 日本語のみ（`Locale(identifier: "ja_JP")` を随所で強制） |
| コンセプト | 「地図は入口、記録が本体」— 日本47都道府県への訪問を地図に刻み、訪問ごとの記憶（日時・メモ・写真・気分など）を記録する旅行記録アプリ |
| 名前の由来 | いろは歌は仮名47文字を重複なく使った詩。日本の47都道府県と数が一致することがアプリ名の核心 |

アプリは **3つのタブ + 各種シート（モーダル）** で構成される。都道府県ごとの「行った／行っていない」だけでなく、訪問の**回数・日時・気分・移動手段・同行者・写真**まで記録できる点が中心的な差別化要素。

## 2. 画面構成の全体像

```
IrohaApp (@main)
└── ContentView
     ├── TabView
     │    ├── ① 地図タブ            MapTabView
     │    ├── ② 旅の軌跡タブ        TimelineView
     │    └── ③ 記録タブ            JourneyTrackerView
     │           └── NavigationLink(⚙️) → SettingsView
```

## 3. 初回起動フロー

### 3.1 オンボーディング（`OnboardingView`）

`@AppStorage("onboarding_done")` が `false` の間、`ContentView` の最前面に overlay 表示される全画面ビュー。紫のグラデーション背景 + 3ページ構成。

| ページ | タイトル | 本文 | イラスト |
|---|---|---|---|
| 1/3 | いろは歌は47文字 | 日本は47都道府県。すべての旅を、地図に刻もう。 | いろは歌48文字を8列の縦書きで表示し、「い・ろ・は」の3文字だけ強調 |
| 2/3 | タップで記録 | 日時とひとことメモを残すだけ。写真も添えられます。 | 同心円のシンプルなイラスト |
| 3/3 | 旅の記録が自動でまとまる | 3日以内の連続旅行はひとつの旅として表示されます。 | タイムライン風の横線+カードイラスト |

- ページ送りボタンは「次へ」→（最終ページのみ）「はじめる」に変化
- 最終ページ以外は「スキップ」ボタンが常時表示され、即座に完了扱いにできる
- ステップインジケーターは `01 / 03` 形式 + ドット

### 3.2 iCloud同期の案内（`CloudSyncOnboardingView`）

オンボーディング完了直後、`cloud_sync_onboarding_done` が `false` の間だけ1回シート表示される（スワイプで閉じられない `.interactiveDismissDisabled()`）。

- 「旅の記録は iCloud に自動保存されます」という前提を伝える画面（**iCloud同期はデフォルトで ON**）
- 訴求ポイント: 自動同期 / 削除しても復元可能 / 複数端末で同じデータ / iCloud容量を使用する旨の注記
- ボタンは2つ:
  - **「OK」** — 同期ONのまま続行
  - **「同期をOFFにする」** — 確認アラート → OFFに設定 →「次回起動時から反映されます」の案内

> 実装コメントに明記されている通り、これは「案E: デフォルトON化」という設計判断であり、Apple純正アプリ（メモ・写真）と同じUXを踏襲している。

## 4. ①地図タブ（`MapTabView`）

### 4.1 日本地図

- Geolonia提供のSVG（`Resources/map-full.svg`）を `WKWebView` にHTMLとして埋め込み、JavaScriptでタップ検出・色更新を行う。**MapKitの地図表示は使用しない**（位置検索APIのみ許可）
- 47都道府県が塗りつぶし形式で表示され、タップで県詳細シートが開く

### 4.2 訪問回数による発色（塗りかけ）

同じ県に複数回訪問しても記録は上書きされず**全件保持**され、回数に応じて色が濃くなる。

| 訪問回数 | 色（HEX） | 意味 |
|---|---|---|
| 0回 | `#DDDAD4` | 未訪問 |
| 1回 | `#C8C4F0` | はじめて |
| 2回 | `#9F97DD` | また行った |
| 3〜4回 | `#7F77DD` | 常連 |
| 5回以上 | `#534AB7` | ホーム |
| 47県すべて訪問済み | `#534AB7`（全県固定） | 全国制覇 |
| 居住のみ（旅行記録なし） | `#E8D9A8`（淡い金茶） | 住んだが旅行記録は0件の県 |

**色の優先順位は 旅行 > 居住**。住んだ県に旅行もしている場合は訪問回数どおりの紫で塗られ、地図から旅行回数がそのまま読み取れる。淡い金茶になるのは「住んだが旅行記録は1件もない」県のみ。

居住県は「N/47」の訪問県数にはカウントされるが、「◯回旅行」の回数には加算されない（5年住んだのを「1回訪問」としないため）。

UI 上の居住表示は、**書式（フォントサイズ・ウェイト・レイアウト）を旅行側と完全に揃え、色相だけを紫 → 金茶に変えて区別する**方針で統一している。サイズやウェイトを変えて目立たなくしようとすると、その差分自体が視線を引いてしまうため。

### 4.3 表示モード切替バー

地図上部の2択チップで表示モードを切り替え。

| モード | 表示 |
|---|---|
| 旅した | 通常の訪問回数カラーリング |
| これから | 未訪問県を強調 |

### 4.4 地方制覇サジェスト

進捗が最も近い地方を「あと N 県で〇〇制覇」という文言で提示し、未訪問県名のチップが横に並ぶ。チップタップで地図がその県にフォーカスし詳細シートが開く。行の右端の✕で当該提案を非表示にできる（表示中は同じ提案を出さない）。

### 4.5 統計バー（`IrohaStatsBar` / `StatsBarView.swift`）

地図下部に常時表示。

| 要素 | 内容 |
|---|---|
| 訪問県数 | `NurikakeNumber`（塗りかけ数字）で `N / 47`（居住県を含む） |
| 住んだ県数 | 家アイコン + 「N県」。居住記録が1件もない場合は非表示 |
| 達成率 | パーセント表示 |
| 進捗バー | グラデーションの横棒 |
| 8地方ドット | 各地方の達成度に応じて下から塗り上がる円。タップで「地方名 N/M」のポップアップを表示（もう一度タップで閉じる） |

### 4.6 バッジコレクションへの導線

画面右下に medal アイコンの円形フローティングボタン。タップで `BadgeCollectionView` をシート表示（[§10](#10-バッジコレクションbadgecollectionview) 参照）。

### 4.7 マイルストーン演出

訪問記録の保存後、達成条件を満たすとトースト表示や桜エフェクトが発火する。詳細は [§11](#11-マイルストーン演出) を参照。

> **廃止済みの旧仕様**: 「長押しで『行きたい』マークを付ける」機能は初期構想にあったが実装されていない（`Prefecture` に該当フラグは存在しない）。

## 5. 県詳細シート（`PrefectureDetailSheet`）

地図タップ・記録タブのハイライト行などから開くモーダル。`presentationDetents([.fraction(0.70), .large])`（下から70%高さ、上スワイプで全画面）。

### 構成（上から順）

| セクション | 内容 |
|---|---|
| ヘッダー | 読み仮名（1文字ずつ字間を空けて表示）・県名（serif体）・地方名・訪問回数（`NurikakeNumber`、5回で満タン表示。居住は回数に含めない） |
| 住んでいた期間 | 居住記録がある場合のみ表示。「2015年4月 〜 2019年3月」+ 期間の長さ（4年）+ 場所。タップで編集 |
| 写真ギャラリー | その県の全訪問記録の写真サムネイルを横スクロール表示（写真がある場合のみ表示）。タップでフルスクリーン表示 |
| 記録ボタン（2つ横並び） | 「今日を記録」/「今日の記録を編集」（当日の記録有無で切替）と「他の日を記録」 |
| 訪問記録一覧 | 新しい順に一覧表示。タップで対応する旅（Trip）の詳細シートを開く／コンテキストメニュー（長押し）で編集・削除 |

### クイック記録の挙動

- その日の記録が **無い場合**: 「今日を記録」ボタンをタップした瞬間に `Visit(prefectureName:, prefectureID:, startDate: Date())` を作成・即保存（タグ・メモなしの最小記録）
- その日の記録が **既にある場合**: ボタンが「今日の記録を編集」に変わり、タップで `VisitFormView` を編集モードで開く（重複記録を防止）
- 「他の日を記録」は常に `VisitFormView` を新規追加モードで開く

### 訪問記録カードの表示内容

日付・旅行スタイルバッジ・気分バッジ・移動手段バッジ・同行者バッジ・場所（あれば）・旅行名（あれば）・メモ（無ければ「メモなし」）・写真サムネイル（複数枚は `+N` 表示）。カードタップで、その訪問が属する旅（Trip）の詳細シートを開く（見つからない場合は直接編集画面へ）。

### 写真の全画面表示

写真サムネイルのタップで黒背景のページめくりビューアを表示。フルサイズ画像の読み込みに失敗した場合はアラートを表示。

## 6. 訪問記録フォーム（`VisitFormView`）

訪問の追加・編集を共用する入力フォーム。`presentationDetents([.large])` で全画面表示。各項目はタップで開閉するアコーディオン形式の行になっている。

### 入力項目一覧

| 行 | 内容 | 備考 |
|---|---|---|
| 種別 | 旅行 / 居住 の2択 | 居住を選ぶと後述の項目が切り替わる。タイトルも「住んだ記録」に変わる |
| 都道府県 | 県名検索（かな/漢字の部分一致）+ 地方ごとにグルーピングされた選択チップ | 県詳細シートから開いた場合は固定され非表示（変更不可） |
| 旅行スタイル | プリセット5種（一人旅 / 家族旅行 / 恋人旅行 / 友達旅行 / その他）+ ユーザーが追加したスタイルの単一選択 | 再タップで選択解除可。**種別=居住のときは非表示**（選択肢がすべて旅行前提のため）。選択肢の増減は設定 →「旅行スタイル」で行う。非表示にしたプリセットを使っている記録を編集した場合、そのスタイルだけ選択肢に残る |
| 旅行日 | 粒度セグメント（年月日 / 年月 / 年）+ 開始日・帰着日 | 種別=旅行のときのみ。年月日はグラフィカルカレンダー、年月・年はホイール。日付が曖昧な記録の詳細は後述 |
| 期間 | 住みはじめた日・引っ越した日 +「現在も住んでいる」トグル | **種別=居住のときのみ**「旅行日」の代わりに表示。トグルONで終了日ピッカーが隠れ「〜現在」表記になる |
| 場所 | フリーテキスト入力 + `MKLocalSearchCompleter` によるサジェスト（最大5件） | 候補選択で緯度経度も保持。「位置情報を削除」で解除可。種別=居住のときはプレースホルダが「住んでいた場所（例：松山市）」に変わる |
| 写真 | `PhotosPicker` で最大10枚まで追加、3列グリッドでプレビュー・削除 | 保存時に並列圧縮（後述） |
| 移動手段 | 車・電車・新幹線・飛行機・バス・船・自転車・徒歩の複数選択（4列グリッド） | 種別=居住のときは非表示 |
| 同行者 | テキスト入力で追加（複数）。過去に入力した同行者名を候補チップとしてサジェスト | 種別=居住のときはラベルが「同居した人」に変わる。候補チップを長押しすると「候補から削除」で以降サジェストされなくなる。過去の記録・旅の軌跡のフィルタは変更されない。同じ名前を手入力で追加し直すと候補に復活する |
| ムード | 楽・癒・感・驚・懐・静の単一選択（円形スタンプ） | 再タップで選択解除可。**種別=居住のときは非表示**（数年間の暮らしを単一の気分スタンプで表せないため） |
| 旅行名 | 任意のフリーテキスト | 種別=居住のときは非表示 |
| メモ | 複数行テキスト入力 | |

編集時のみフォーム最下部に「この記録を削除」ボタンを表示。

### 日付が曖昧な記録（旅行日の粒度）

昔の旅行など具体的な日付を覚えていない場合のために、旅行日の粒度を 3 段階から選べる。旅行日セクションを開くと最上部に粒度セグメントが出る。

| 粒度 | 入力方法 | 表示例 |
|---|---|---|
| 年月日（既定） | グラフィカルカレンダー | 2015年5月3日 |
| 年月 | 年ホイール + 月ホイール | 2015年5月 |
| 年 | 年ホイール | 2015年 |

- 帰着日も同じ粒度で入力できる（例:「2015年5月 〜 2015年6月」）。開始日と同じ月・同じ年なら単一表示に畳まれる
- 年ホイールの範囲は 1940年 〜 今年
- 粒度を切り替えると日付が新しい粒度に丸まる。粗い粒度から戻しても元の日は復元されない（年月日 5/3 → 年月 → 年月日 で 5/31 になる）
- 年月日以外では日タップによる自動遷移が使えないため、「完了」ボタンが開始日 → 帰着日 → セクション閉じるの遷移を担う
- **種別=居住のときは粒度セグメントを表示しない**。居住はもともと期間を年月で表示するため。旅行で粒度を選んだ状態から居住へ切り替えると年月日に戻る

内部では日付を `Date` のまま保持し、年月なら月末・年なら12/31を「代表日」として格納する（今年・今月を選んだ場合は今日でクランプ）。そのため年フィルタ・訪問数・制覇率はそのまま機能する。一方、月日が確定していないと意味をなさない以下の機能からは除外される。

| 機能 | 年月 | 年のみ |
|---|---|---|
| ◯年前の今日（メモリーカード） | 除外 | 除外 |
| 四季バッジ・12ヶ月バッジ | 対象（月は確定するため） | 除外 |
| 旅の自動グルーピング（3日ルール） | 除外（常に単独の旅） | 除外 |
| 「N泊M日」表示・泊数系バッジ | 除外 | 除外 |
| 年フィルタ・訪問数・制覇率 | 対象 | 対象 |

### 保存の挙動

- 保存ボタンは都道府県が未選択の間は無効化
- 保存中はオーバーレイで「保存中…」を表示し二重送信を防止
- 新規に追加した写真は、圧縮処理（長辺2048px以内・5MB以内に自動リサイズ、JPEG品質0.8から段階的に下げて調整）を**最大4並列**でバックグラウンド実行してから `VisitPhoto` として登録
- 保存失敗時は追加した写真をロールバックしてエラーメッセージを表示
- 削除対象の写真は、新方式（`VisitPhoto` リレーション）と旧方式（`Documents/Photos/` のファイル）の両方に対応して削除処理を振り分け

## 7. ②旅の軌跡タブ（`TimelineView`）

全訪問記録を時系列（年 → 月 → 旅）でグルーピングして表示するフィード画面。ナビゲーションバー右上に「＋」ボタンがあり、新規訪問記録を直接追加できる。

### 構成（上から順）

| 要素 | 内容 |
|---|---|
| メモリーカード（`MemoryCardView`） | 「◯年前の今日」に訪問した記録があれば表示。複数件ある場合は横スワイプで送れる。✕で当セッション中のみ非表示可（設定でも表示自体をOFFにできる） |
| 年切替（`YearSwitcher`） | 「すべて」+ 年タブの横スクロール |
| フィルターバー | スタイル / ムード / 移動手段 / 同行者 の4種のメニューで絞り込み。条件適用中は「クリア」チップが出現 |
| 年ヘッダー | 選択中の年（`NurikakeText` で塗りかけ表示）+ その期間の「N県・M旅」+ シェアボタン |
| 月別の旅カード | 月ヘッダー区切りで、検出された「旅（Trip）」を時系列に縦並び表示 |
| 「時期不明」セクション | 年しか分からない記録をまとめる見出し。各年の**末尾**に1回だけ出す（年月の記録は月が確定するので通常の月ヘッダーに載る） |
| 居住行 | 住みはじめた月に1件だけ「◯◯県に住みはじめた」の専用行を差し込む（家アイコン＋金茶）。期間中の各月には繰り返し表示しない。フィルタ適用中は非表示 |

### 旅ルートの自動検出（`TripDetector`）

- **居住記録は検出の入口で除外される**（居住は期間が数年に及ぶため、3日ルールに混ぜると居住期間中の全旅行が1つの巨大な旅に併合されてしまう）
- **日付が曖昧な記録（年月 / 年のみ）も確定日付の記録から切り離され、常に単独の旅になる**。代表日が実際の訪問日と一致しないため、時系列の途中に混ざると前後の確定日付どうしの連結まで分断してしまう（例:「5/1 東京」「2015年 北海道」「5/3 千葉」で東京と千葉が別の旅に割れる）
- 残った訪問を開始日の昇順にソートし、**直前の訪問の帰着日（`effectiveEndDate`）から次の訪問の開始日までのカレンダー日数差が3日以内**であれば同じ「旅」としてグループ化する
- 1県だけの旅も `Trip` として扱われる（`isSingleVisit` で判定可能）
- `Trip` は非永続化の動的生成データ。IDはFNV-1aハッシュによる決定的UUID（同じ入力なら常に同じIDになる）。ハッシュの種はグループを構成する訪問の識別子で、同一県・同一年の曖昧な記録どうしでIDが衝突しないようにしている

### 旅カードの表示内容

- 1県のみの旅: 県名 + スタイルバッジ + ムードバッジ
- 複数県の旅: 「県名 → 県名 → …」の経路表示 + 「N泊M日」バッジ
- 移動手段アイコン（最大3種）・日付（範囲）・場所/旅行名/メモ（横スクロール）・全訪問の写真サムネイル横並び

タップで `TripDetailSheet` を開く。

### 年ヘッダーのシェア

「シェア」ボタンから、その年（または「すべて」選択時は全期間）の訪問県を強調した日本地図画像を生成し、OS標準の共有シートを開く。詳細は [§14](#14-マップ画像シェア) を参照。

## 11. マイルストーン演出

訪問記録の保存時、`MapViewModel.detectMilestone()` が新旧の訪問状況を比較して達成を検出し、**優先度順に1種類だけ**アニメーションを発火する（複数条件を同時に満たしても1回のみ）。

**優先度: 全国制覇 > 半分制覇 > 地方制覇 > N県マイルストーン > 初訪問**

| 種類 | 達成タイミング | 演出 |
|---|---|---|
| 初訪問 | 0→1県 | 該当県がふわっと紫に染まるフェードアニメーション |
| N県達成 | 5/10/15/20/30/35/40/45県 | トースト「N県達成！」+ 地図が一瞬拡大して戻る |
| 半分制覇 | 25県 | トースト「25県達成！半分制覇！」+ 桜エフェクト（light）+ 地図拡大 |
| 地方制覇 | いずれかの地方の全県訪問 | 桜エフェクト（medium）+ 該当地方の県が一時的にフラッシュ |
| 全国制覇 | 47県すべて訪問 | 桜エフェクト（grand）+ 北から南へ順に色が伝播するウェーブアニメーション（3秒） |

各マイルストーンは達成済みフラグが `UserDefaults` に保存され、二度目以降は再発火しない。設定画面の「全データをリセット」「アプリを初期化」でこれらのフラグもクリアされ、再度演出を見られるようになる。桜エフェクトは `CAEmitterLayer` による花びらパーティクルで、強度（light/medium/grand）によって発生数・発生時間が変わる。

### 旅行スタイルの管理（`TravelStyleSettingsView`）

設定 →「旅行スタイル」から遷移する。2セクション構成。

| セクション | 内容 |
|---|---|
| プリセット | 5種を一覧表示。各行に使用件数とトグルがあり、OFF にすると記録フォームのピッカーと旅の軌跡のフィルタから消える。名前・色・アイコンは変更できない |
| 自分のスタイル | ユーザーが追加したスタイルの一覧（最大20件）。プリセットと同じくトグルで表示・非表示を切り替えられる。名前をタップすると編集シート、長押しで削除メニュー。「＋ スタイルを追加」で新規作成 |

追加・編集シート（`TravelStyleEditorView`）では、名前（12文字まで）・色（伝統色12色）・アイコン（SF Symbols 24種）を選ぶ。画面上部に保存前のバッジプレビューを表示する。編集時は最下部に「このスタイルを削除」ボタンが出る。

非表示と削除の違い:

| | 選択肢・フィルタ | 過去の記録のバッジ | 元に戻せるか |
|---|---|---|---|
| 非表示（トグル OFF） | 消える | 残る | トグル ON で戻る |
| 削除 | 消える | 消える（`tag` が nil になる） | 戻せない |

削除時の挙動:

- そのスタイルを使っている記録が N 件あれば「N件の記録からこのスタイルが外れます。記録そのものは削除されません。」と警告する
- 承認すると、該当記録の `tag` を nil にしてからレコードを削除する（1トランザクション）
- 結果としてスタンプ「三つの旅路」が未獲得に戻ることがある（獲得状態は毎回記録から再計算するため）

プリセットを非表示にしても、過去の記録に付いたバッジは残る。その記録を編集で開いた場合、非表示のスタイルだけ選択肢に残るため、保存し直しても勝手に外れない。

「アプリを初期化」を実行すると、プリセットの非表示設定とユーザー定義スタイルの両方が消える。「全データをリセット」では消えない（記録・写真・マイルストーンのみが対象のため）。

## 13. プライバシーポリシー・ライセンス画面

### `PrivacyPolicyView`

セクション見出し付きの静的テキスト表示画面。要旨:

- 個人情報は収集・送信しない。記録データはすべて端末内保存
- 写真ライブラリへのアクセスは写真添付機能利用時のみ発生し、選択された写真はアプリ内にコピーされる
- 場所検索でApple地図検索サービスを利用するが、検索クエリの収集・保存は行わない

## 14. マップ画像シェア

旅の軌跡タブの年ヘッダーにある「シェア」ボタンから、訪問済み県を強調した日本地図画像をSNS等に共有できる。

### 生成の流れ

1. 選択中の年（「すべて」の場合は全期間）でフィルタした訪問データから `VisitStats` を作成
2. 非表示の `WKWebView` にSVGをロードし、`takeSnapshot` でマップ画像（UIImage）化
3. マップ画像 + 統計情報を `ShareCardView`（SwiftUI）に合成し、`ImageRenderer`（3倍スケール）で最終画像を生成
4. `UIActivityViewController` でOS標準の共有シートを表示（画像 + テキストメッセージ）

### 共有カードに含まれる要素

- 年ラベル（「2025年の旅」等、「すべて」選択時は「すべての旅」）
- マップ画像（280×280）
- 「訪問数 / 47」「地方制覇数 / 8」の2列統計
- 8地方すべてのチップ（制覇済みはチェックマーク付きで強調表示）
- 「い ろ は」のロゴテキスト
- 共有テキスト: `{年}{訪問数}/47 都道府県制覇！ #いろは #旅行記録`

> 旅単位の写真コラージュ画像（複数の旅の写真をまとめた「旅まとめ画像」）は未実装（v1.1想定機能）。

## 15. データモデル（開発者向け）

永続化層は **SwiftData（`Visit` / `VisitPhoto`）** + **静的マスタ struct（`Prefecture`）** + **動的集計ヘルパー（`VisitStats`）** の三層構造。

### Prefecture（静的 struct、SwiftData外）

CloudKit互換性確保（`@Attribute(.unique)` が使えない・複数端末でのseed重複回避）のため、SwiftDataモデルではなくコード埋め込みのstructとして47都道府県を保持する。

| フィールド | 型 | 内容 |
|---|---|---|
| `id` | Int | 都道府県コード（1〜47） |
| `name` | String | 県名（例: "北海道"） |
| `nameKana` | String | 読み仮名 |
| `region` | Region | 8地方のいずれか |
| `latitude` / `longitude` | Double | 県庁所在地などの代表座標 |
| `distanceFromTokyo` | Double | 東京からの直線距離（km） |

訪問状態（訪問済みか・何回か）はPrefecture自体は保持せず、`VisitStats` が `Visit` の集合から動的に算出する。

### Visit（SwiftData `@Model`、CloudKit同期対象）

| フィールド | 型 | 内容 |
|---|---|---|
| `prefectureName` / `prefectureID` | String / Int | 訪問先（名前は表示用、IDが実際の参照キー） |
| `kind` | VisitKind? | 記録種別（旅行 / 居住）。`nil` は旧データで旅行扱い |
| `startDate` | Date | 訪問開始日 / 居住開始日（旧属性名 `date` からライトウェイトマイグレーション済み） |
| `endDate` | Date? | 帰着日。`nil` の場合は日帰り。**旅行専用** |
| `residenceEndDate` | Date? | 居住の終了日。**居住専用**（`endDate` と分けているのは `nil` の意味が衝突するため） |
| `isResidenceOngoing` | Bool | 現在も居住中か。true なら `residenceEndDate` は `nil` |
| `note` | String | メモ |
| `tag` | String? | 旅行スタイル ID（種別と直交する軸。居住でも設定できる）。プリセットは `"solo"` 等、ユーザー定義は `"u:<UUID>"`。未選択は nil |
| `mood` | VisitMood? | 気分スタンプ |
| `transports` | [String] | 移動手段（複数可、rawValue配列） |
| `tripName` | String | 旅行名 |
| `companions` | [String] | 同行者名の配列 |
| `location` / `locationLatitude` / `locationLongitude` | String / Double? | 訪問場所（フリーテキスト+任意で緯度経度） |
| `photos` | [VisitPhoto]? | 写真リレーション（cascade削除） |
| `photoFilename` 等（レガシー） | — | 旧 `Documents/Photos/` 方式の写真。移行完了まで併存 |

### VisitPhoto（SwiftData `@Model`、CloudKit同期対象）

| フィールド | 内容 |
|---|---|
| `imageData` | フルサイズ画像データ（`.externalStorage`、CloudKit Assetとして同期。最大2048px/5MBに強制縮小） |
| `thumbnailData` | サムネイル（300px、JPEG品質0.7） |
| `orderIndex` | 表示順 |
| `legacyFilename` | 旧方式からの移行元ファイル名（重複検出キー） |

### Trip（非永続化 struct）

`TripDetector.detect(from:)` が `Visit` の配列から動的に生成する。`startDate` / `endDate` / `isSingleVisit` / `tripName` / `prefectureNames` を計算プロパティとして持つ。IDはFNV-1aハッシュによる決定的UUID。

### 主要な enum

| enum | 値 |
|---|---|
| `Region` | hokkaido, tohoku, kanto, chubu, kinki, chugoku, shikoku, kyushu（8地方） |
| `VisitKind` | travel（旅行）, residence（居住）。`.none` を持たず、未設定は `kind == nil` で表す |
| `TravelStylePreset` | solo（一人旅）, family（家族旅行）, couple（恋人旅行）, friends（友達旅行）, other（その他）＋レガシー3種（dayTrip, stay, lived）。ユーザー定義スタイルは `TravelStyleRecord`（SwiftData）で持つ |
| `TravelStylePalette` | 伝統色ベースの配色。ユーザーが選べるのは 12 色（紅 / 朱 / 黄檗 / 鶯 / 苔 / 錆青磁 / 群青 / 桔梗 / 江戸紫 / 蘇芳 / 樺 / 鉄紺） |
| `VisitMood` | none, tanoshi（楽）, iyashi（癒）, kandou（感）, odoroki（驚）, natsukashi（懐）, shizuka（静） |
| `VisitTransport` | none, car（車）, train（電車）, shinkansen（新幹線）, airplane（飛行機）, bus（バス）, ship（船）, bicycle（自転車）, walking（徒歩） |
| `TravelerTier` | beginner, intermediate, advanced, master（[§10](#10-バッジコレクションbadgecollectionview)参照） |
| `BadgeCategory` | road（旅の道）, skill（旅の技）, proof（旅の証） |

### iCloud（CloudKit）同期

- `ModelContainer` は起動時に `cloudKitDatabase: .private("iCloud.com.qumo.Iroha")` の有無で構築（`cloud_sync_enabled` の値に依存、デフォルト`true`）
- 同期対象スキーマは `[Visit.self, VisitPhoto.self]`。`Prefecture` は静的structのため同期対象外
- ON/OFF切替はアプリ再起動が必要（`ModelContainer` が起動時に固定されるため）
- `CloudSyncStatusObserver` が `CKAccountStatus`（Apple IDサインイン状態）と `NWPathMonitor`（ネット接続）を監視し、設定画面に同期状態を表示する

## 16. 技術スタック

| 項目 | 内容 |
|---|---|
| 対応OS | iOS 18.0以上 |
| UI | SwiftUI（`WKWebView` / `UIActivityViewController` / `PhotosPicker` などUIKit連携を部分利用） |

| アーキテクチャ | MVVM + `@Observable` / `@MainActor` |
| サードパーティ製ライブラリ | 不使用（審査リスク回避方針、アクセス解析ツールも含めない） |

## 17. 未実装・既知の差分

企画書（`plans/iroha-feature.md` 等）に記載がありながら、現バージョン（1.0.5）のソースコード上には存在しないことを確認した機能:

| 機能 | 状態 |
|---|---|
| 県名検索オーバーレイ（地図タブから直接） | 未実装。県名検索は訪問記録フォーム内のみ |
| 記念日通知（「京都の旅から1年」等のプッシュ通知） | 未実装。画面内の「今日の記憶」カードのみ実装済み |
| 旅リマインド通知 | 未実装 |
| 年次レビューカード（Wrapped風の年間まとめ） | 未実装 |
| 旅まとめ画像のSNSシェア（写真コラージュ） | 未実装。年別マップ画像シェアのみ実装済み |
| ホーム画面ウィジェット | 未実装（`WidgetKit` 関連コード・ターゲット無し） |
| JSONバックアップ・復元 | **廃止済み**。iCloud自動同期に置き換えられている（[§12](#12-設定画面settingsview) 参照） |

上記のうち「JSONバックアップ・復元」はプライバシーポリシー本文（[§13](#13-プライバシーポリシーライセンス画面)）にも言及が残っており、現在の実装との不整合がある。
